# Отчёт о выполнении практического задания: Многопоточность в Spring Boot

## 1. Введение и архитектура приложения

В рамках выполнения задания разработан многопоточный сервис на базе каркаса **Spring Boot 3** (Java 21).  
Архитектура приложения построена по классическому многослойному принципу:

1. **Слой представления (Controller)**: `com.example.demo.controller.ThreadController`  
   - Предоставляет REST API для запуска многопоточной демонстрации (`POST /api/threads/run-demo`) и мониторинга активных потоков (`GET /api/threads/active`).
2. **Сервисный слой (Service)**: `com.example.demo.service.ThreadService`  
   - Инкапсулирует бизнес-логику создания, именования, запуска и координации потоков, а также получение снимка состояния всех активных потоков JVM.
3. **Слой задач и потоков (Task / Model)**:
   - `com.example.demo.task.WorkerThread` — реализация потока через наследование базового класса `java.lang.Thread`.
   - `com.example.demo.task.Task` — реализация задачи через интерфейс `java.lang.Runnable`.
   - `com.example.demo.model.ThreadInfoDto` — DTO для передачи структурированной информации о потоках через REST API.
4. **Конфигурация и запуск**: `com.example.demo.DemoApplication`  
   - Точка входа Spring Boot, содержащая `CommandLineRunner` для автоматического запуска демонстрации при старте приложения.

## 3. Этапы выполнения задания

### Этап 1. Создание каркаса и классов задач
Для демонстрации обоих подходов к созданию потоков в Java были реализованы два класса:
1. **Через `Thread` (`WorkerThread`)**:
   - Наследуется от `java.lang.Thread`.
   - В конструкторе принимает имя потока, количество шагов и задержку.
   - Переопределяет метод `run()`, выводя имя потока и порядковый номер шага (`[%s] Порядковый номер: %d`).
2. **Через `Runnable` (`Task`)**:
   - Реализует функциональный интерфейс `java.lang.Runnable`.
   - Представляет независимую исполняемую задачу. В методе `run()` с помощью `Thread.currentThread().getName()` определяет имя исполняющего потока и выводит порядковый номер шага.

### Этап 2. Создание сервисного класса и именование потоков
Создан класс `ThreadService` с аннотацией `@Service`:
- Потокам присвоены понятные, говорящие имена:
  - `CounterWorker` — экземпляр `WorkerThread` (подход через `Thread`);
  - `LoggerThread` — экземпляр `Thread`, в который передана задача `Task` (подход через `Runnable`).
- Запуск обоих потоков осуществляется вызовом метода `.start()`.
- Добавлено корректное ожидание завершения потоков через `.join()`.

### Этап 3. Получение и вывод списка всех активных потоков
В классе `ThreadService` реализован сбор информации обо всех потоках JVM:
- Метод `Thread.getAllStackTraces().keySet()` позволяет получить полный набор всех активных потоков JVM.
- Метод `printActiveThreads()` выводит в консоль форматированную таблицу с атрибутами каждого потока:
  - ID потока;
  - Имя потока (включая созданные `CounterWorker` и `LoggerThread`);
  - Текущее состояние (`NEW`, `RUNNABLE`, `TIMED_WAITING`, `WAITING`, `TERMINATED`);
  - Приоритет потока;
  - Признак демона (`isDaemon`);
  - Имя группы потоков (`ThreadGroup`).
- Метод `getActiveThreads()` преобразует данные в список `ThreadInfoDto` для отдачи через REST контроллер.

### Этап 4. Интеграция со Spring Boot и REST контроллер
- В `DemoApplication` добавлен бин `CommandLineRunner`, который автоматически выполняет демонстрацию многопоточности и выводит таблицу активных потоков в консоль при запуске приложения.
- Создан REST-контроллер `ThreadController`, позволяющий вызывать демонстрацию удаленно (`POST /api/threads/run-demo`) и инспектировать потоки в формате JSON (`GET /api/threads/active`).

### Этап 5. Тестирование и верификация
- Разработаны автоматические тесты `ThreadServiceTest` и `ThreadControllerTest`, покрывающие:
  - корректность жизненного цикла потока `WorkerThread`;
  - корректность выполнения задачи `Task` в потоке `Runnable`;
  - получение списка активных потоков;
  - валидацию HTTP-ответов контроллера через `MockMvc`.
