# Краткий отчёт: сервер URL-задач на BlockingQueue

## 1. Реализация Producer–Consumer

В `src/main/java/com/example/demo/taskqueue/` добавлены:

- `UrlTaskServer` — производители, ограниченная очередь и потребители;
- `HttpPageLoader` — загрузка страницы и извлечение HTML-заголовка;
- `UrlTaskApplication` — ввод URL и вывод результатов.

Приложение принимает URL аргументами или из UTF-8 файла через `--file`. В файле пропускаются пустые строки и комментарии `#`. Повторный URL считается самостоятельной задачей, имеющей свой индекс.

По умолчанию работают **3 Producer**, **4 Consumer** и `BlockingQueue`, реализованная как **`ArrayBlockingQueue` ёмкостью 8**. Производители распределяют между собой входной список и выполняют `queue.put(task)`. При заполнении очереди Producer блокируется, обеспечивая обратное давление без потери задач.

Потребители выполняют `queue.take()`: при пустой очереди поток ожидает, не опрашивая её в активном цикле. Для Producer и Consumer выделены разные `ExecutorService`, чтобы заблокированные производители не заняли все потоки, необходимые для обработки очереди.

## 2. Загрузка и извлечение title

Consumer получает URL, скачивает страницу через `HttpURLConnection` и извлекает первый `<title>` стандартным HTML-парсером `ParserDelegator`. HTML-сущности декодируются, лишние пробелы нормализуются. Кодировка берётся из `Content-Type`, по умолчанию используется UTF-8. JavaScript не выполняется.

Настроены отдельные таймауты соединения и чтения по **3 секунды**; это не общий срок выполнения всей партии. Размер загружаемого тела ограничен **1 MiB**. Соединение и входной поток закрываются после обработки.

Для каждой задачи сохраняются URL, HTTP-код, заголовок или причина ошибки, время обработки, имена Producer и Consumer. Время задачи включает загрузку и разбор, но не ожидание в очереди. Итоговый список сортируется по исходному индексу; порядок фактического завершения может отличаться.

HTTP-ошибка, таймаут или неверный URL не останавливают другие задачи. Если успешная страница не содержит `<title>`, возвращается пустой заголовок. Прерывание Consumer останавливает партию; координатор отслеживает аварийное завершение потребителей, чтобы не зависнуть на производителе, ожидающем свободного места.

## 3. Завершение потоков

Координатор сначала дожидается всех производителей, затем добавляет в хвост очереди **по одному стоп-маркеру на Consumer**. Обычные URL уже стоят перед маркерами. Получив маркер, Consumer завершает цикл; координатор ожидает все потребительские Future.

Оба пула завершаются в `finally`. При отмене прерываются также задачи, ожидающие `put()` и `take()`. В штатном результате проверяется, что число обработанных задач равно размеру входного списка.

## 4. Фактические результаты

Локальная демонстрация использовала настоящий HTTP-сервер, **3 Producer, 4 Consumer, очередь ёмкостью 2** и таймаут чтения/соединения 300 мс:

| Показатель | Результат |
| --- | ---: |
| Всего URL-задач | 17 |
| Успешных загрузок с заголовком | 13 |
| Успешных страниц без title | 1 |
| HTTP 404 | 1 |
| Таймаут | 1 |
| Некорректный URL | 1 |
| Общее время партии | 581,428 мс |

Повторная загрузка `/page/1` обработана отдельно. Заголовок `Страница /page/1 &amp; очередь` извлечён как `Страница /page/1 & очередь`. Оба пула сообщили `terminated=true`. Полный вывод: [TASK_QUEUE_RESULTS.txt](TASK_QUEUE_RESULTS.txt).

Также проверен консольный ввод из `urls-queue.txt`: все **4 публичные страницы вернули HTTP 200**. Извлечены `Example Domain` для example.com/org/net и `IANA-managed Reserved Domains` для страницы IANA. Время партии — **987,948 мс**. Полный вывод: [TASK_QUEUE_PUBLIC_RESULTS.txt](TASK_QUEUE_PUBLIC_RESULTS.txt). Эти задержки относятся к конкретным запускам и не являются гарантией производительности.

## 5. Запуск и проверки

Из `multithreading/demo` с JDK 17 или новее:

```sh
mkdir -p target/taskqueue-demo
javac -encoding UTF-8 -d target/taskqueue-demo src/main/java/com/example/demo/taskqueue/*.java
java -cp target/taskqueue-demo com.example.demo.taskqueue.UrlTaskApplication --file urls-queue.txt

# URL можно передать напрямую.
java -cp target/taskqueue-demo com.example.demo.taskqueue.UrlTaskApplication https://example.com https://example.org

# Локальная воспроизводимая демонстрация.
javac -encoding UTF-8 -cp target/taskqueue-demo -d target/taskqueue-demo src/test/java/com/example/demo/taskqueue/LocalPageServer.java src/test/java/com/example/demo/taskqueue/LocalUrlTaskDemo.java
java -cp target/taskqueue-demo com.example.demo.taskqueue.LocalUrlTaskDemo

sh ./mvnw -Dtest=com.example.demo.taskqueue.UrlTaskServerTest test
sh ./mvnw test
```

Добавлены **8 тестов**: конкурентная обработка без потерь и повторной обработки одной задачи; частичные ошибки и повторные URL; реальная HTTP-загрузка и title; таймаут, неверный адрес и слишком большая страница; разбор HTML; прерывание заблокированных потоков; авария Consumer; пустой список, параметры и файловый ввод.

Все **81 тест проекта**, включая новые восемь, прошли без ошибок и падений. Компиляция `javac -Xlint:all` не выдала предупреждений. Сетевые проверки выполнялись вне sandbox с разрешёнными сокетами; для полного набора явно подключался Mockito javaagent, как в предыдущих заданиях. При публичной HTTPS-проверке использовались системные корневые сертификаты; проверка TLS не отключалась.

## Вывод

Реализован сервер задач, в котором `BlockingQueue` безопасно передаёт URL между несколькими производителями и потребителями. Ограниченная очередь регулирует скорость поступления задач, обработка ошибок сохраняет результаты остальных URL, а стоп-маркеры обеспечивают завершение после обработки накопленной очереди.
